# Deploying

One [Render](https://render.com) web service runs the API, which also serves the built web app, so both share one address. The database is [Neon](https://neon.com) Postgres. Both have a free plan. Render builds [`apps/backend/Dockerfile`](../apps/backend/Dockerfile) and deploys a commit once its checks pass on GitHub; the service is declared in [`render.yaml`](../render.yaml).

## Configuration

| Variable                  | Where it comes from                                                            |
| ------------------------- | ------------------------------------------------------------------------------ |
| `DATABASE_URL`            | Neon's **direct** connection string (host without `-pooler`), set by hand      |
| `BETTER_AUTH_SECRET`      | Generated by Render                                                            |
| `LLM_API_KEY`             | Optional, set by hand. Without it the AI actions answer "AI is not configured" |
| `NODE_ENV`, `TRUST_PROXY` | Fixed in `render.yaml`                                                         |
| `RENDER_EXTERNAL_URL`     | Set by Render. The API uses it as its base URL and trusted origin              |

The container applies pending migrations when it starts, which is why the direct connection is required.

## First deploy

1. **Database.** Create a Neon project in the region nearest Render's Frankfurt. In **Connect**, turn **Connection pooling** off and copy the connection string.
2. **Service.** In Render choose **New +**, **Blueprint**, then the repository and the `main` branch. Fill `DATABASE_URL` (and optionally `LLM_API_KEY`) and apply.
3. **Check.** Open the service address. `/health/ready` answers `ok` once the database is reachable. Sign up, create a board, add a task, reload.
4. Put the address in the README and the repository description.

Without a Blueprint, create a **Web Service** with the same settings: runtime Docker, Dockerfile `apps/backend/Dockerfile`, context `.`, instance type Free, health check `/health/live`, auto-deploy after CI checks pass, and the variables above.

## Releases

Merge to `main`. When the checks pass, Render builds the image and replaces the running service. A migration follows expand, then contract: the release that adds a column ships before the one that drops what it replaced.

## Rolling back

Revert the commit on `main` and let the pipeline deploy it. For an emergency, roll back to the previous deploy under the service's **Events** in Render. A migration that has run is not undone.

## Free plan limits

Render requires a payment method on file before it creates a service, even on the free plan, which is not charged. A free service spins down after 15 minutes without traffic, so the first request after a quiet period takes about a minute. Free services share 750 instance hours a month. Neon's free plan needs no card.

## Running the production image locally

```sh
pnpm db:up && pnpm db:deploy
docker build -f apps/backend/Dockerfile -t kanban .
docker run --rm -p 3001:3001 \
  -e DATABASE_URL=postgresql://postgres:postgres@host.docker.internal:5432/kanban \
  -e BETTER_AUTH_SECRET=$(openssl rand -base64 32) \
  -e BETTER_AUTH_URL=http://localhost:3001 \
  -e TRUSTED_ORIGINS=http://localhost:3001 \
  kanban
```

The web app and the API answer on http://localhost:3001.
